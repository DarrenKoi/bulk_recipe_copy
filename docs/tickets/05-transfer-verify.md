# 05: 전송과 검증

**What to build:** 수집이 끝난 job이 대상 장비마다 스레드 1개·FTP 연결 1개로 파일을 순차로
올리고, 같은 경로를 다시 내려받아 SHA-256으로 대조합니다. 충돌이 없는 대상으로의 복사가
끝까지 됩니다. 덮어쓰기 허락이 없는 경우(이 티켓에선 전부)는 첫 쓰기 전 재확인으로 보호합니다.

**Blocked by:** 02, 04

**Status:** ready-for-agent

- [x] 파일 하나의 순서: 필요한 폴더 `mkdir` → 올리기 직전 해시(스냅샷 바이트를 메모리로 읽어 manifest와 비교, 같은 바이트를 `put`에) → `put` → 재다운로드 SHA-256 → `verified` 또는 `failed("해시 불일치")`
- [x] 올리기 직전 해시가 다르거나 파일이 없으면 원격 쓰기 없이 그 job의 남은 `pending`이 `failed`(재수집은 12에서)
- [x] 첫 쓰기 전 재확인: 대상에 `.idp`나 raw 폴더가 이미 있으면 그 (대상, 레시피) 쌍은 쓰지 않고 `failed("확인 뒤 대상에 생김")`. 조회 실패는 "없음"이 아님
- [x] `TransferUncertain`은 `uncertain`, 임시 경로 기록, 지우지 않음
- [x] 연결이 끊기면 재연결해 같은 파일부터. 재시도 상한을 넘기면 그 장비의 남은 파일은 `failed("연결 실패")`
- [x] job의 대상들이 동시에 돎(운영). 동기 hook에선 순차
- [x] pytest: 가짜 장비 끝에서 파일이 바이트 그대로 있음, 해시 불일치, 손상된 스냅샷이면 대상 무변경, raw 폴더만 생긴 대상은 쌍 전체 `failed`, rename 응답 유실 → `uncertain`, 연결 끊김과 재시도 소진

**Notes:**

- 파일 하나의 실제 순서는 올리기 직전 해시 → 첫 쓰기 전 재확인(레시피의 첫 파일에서만) → `mkdir` → `put` → 재다운로드 SHA-256입니다. 해시를 `mkdir`보다 앞에 둔 것은 손상된 스냅샷일 때 빈 폴더조차 대상에 만들지 않기 위해서입니다(스펙 "원격 쓰기를 시작하지 않고").
- 스냅샷 손상은 같은 스냅샷을 쓰는 job 전체의 남은 `pending`을 `failed("스냅샷 손상")`로 만듭니다. 티켓 12에서 재수집 규칙으로 바뀌었습니다.
- 재시도는 같은 파일에서 연속으로 실패한 횟수로 셉니다. 파일 하나가 끝나면 다시 0입니다. 재시도를 다 쓴 순간 `put`까지 끝나고 검증만 못 한 파일은 `failed`가 아니라 `uncertain("검증 전 연결 실패")`입니다. 근거 없이 실패로 두면 재시도 job이 자기 파일에 막히기 때문입니다.
- 장비가 거부한 쓰기(`error_perm`, 5xx)는 재시도하지 않고 그 파일만 `failed("장비 거부: …")`입니다.
- 연결 진입(로그인) 단계의 `error_perm`(530 등)은 파일 거부와 구분합니다. 다시 붙어도 같으므로 그 장비의 남은 파일을 모두 `failed("로그인 거부: …")`로 두고 작업자를 끝냅니다.
- `TransferUncertain` 뒤에는 `FtpClient`가 이미 연결을 버렸으므로, 그 파일을 `uncertain` + 임시 경로로 남긴 다음 파일은 새 연결로 이어 갑니다.
- 전송 크기 상한은 스냅샷을 상한 + 1 바이트까지만 읽어 판단합니다. 넘는 파일은 해시하지 않고 `failed("전송 크기 상한 초과")`입니다.
- 작업자의 예상 못 한 예외(결정 8): 잡고 있던 파일은 대상에 쓰였는지 알 수 없으므로 `uncertain("작업자 오류: <예외 이름>")`, 그 장비의 남은 `pending`은 같은 사유로 `failed`, traceback은 로그에 남기고 작업자를 끝냅니다. 실행 중인 프로세스에 `in_progress`가 남으면 job이 끝나지 않고(티켓 10 뒤에는 장비도 붙잡으므로) 재기동 대조(12)까지 기다리지 않습니다.
- 실패·불명확 file은 결과 트리(08) 전까지 `GET /api/jobs/{id}`의 `problems`에 평평하게 나옵니다.
- 범위 밖으로 둔 것: `.idw` 재확인·전송(07), 대상에만 있는 파일 수, 취소 플래그(09), 재수집(12).
