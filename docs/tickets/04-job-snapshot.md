# 04: job 생성과 스냅샷 수집

**What to build:** 레시피 여러 개와 대상 장비 여러 대를 골라 job을 만들면, 원본을 job당 한
번 로컬 스냅샷으로 받고 manifest를 확정합니다. 작업 목록과 상세 화면에서 수집 상태(`대기 |
수집 중 | 완료 | 차단(사유)`)를 봅니다. 아직 대상에는 쓰지 않습니다. SQLite job 저장소,
부팅 때 뜨는 스케줄러 스레드(이 단계에선 한 번에 job 하나), 테스트용 "큐가 빌 때까지 처리"
동기 hook이 여기서 생깁니다.

**Blocked by:** 01, 03

**Status:** ready-for-agent

- [x] `POST /api/jobs`: 실행자는 인증 신원, 원본·대상은 명부의 Hitachi 장비, 원본 ∉ 대상, class·idw·idp는 경로 성분으로 유효(`/`·`..`·빈 값 금지), 조립 경로가 고정 레이아웃 안. 대상이나 레시피가 비면 거부
- [x] 수집이 끝나면 manifest·file 행(대상 × 파일, `pending`)·수집 결과 `완료`를 SQLite 한 트랜잭션으로 기록. 부분 스냅샷은 쓰지 않음
- [x] manifest 해시는 (상대 경로, 크기, SHA-256)을 경로순 정렬해 계산. mtime·로컬 폴더 이름 제외
- [x] 대상 수가 스레드 상한보다 많거나 스냅샷 총량 상한을 넘으면 생성 거부
- [x] `GET /api/jobs`, `GET /api/jobs/{id}`가 수집 결과를 보여 줌. 화면: 대상 선택 → 실행 → 작업 목록·상세(몇 초마다 갱신)
- [x] 12 전까지 재기동 시 미완료 job을 자동으로 다시 돌리지 않음 (티켓 12에서 재기동 대조 복구로 대체)
- [x] pytest가 동기 hook으로 job 생성 → 수집 완료, 경로 성분 거부, 상한 거부를 시험함

**Notes:** 수집 전후 목록 비교(원본 변경 탐지)는 티켓 11, `대기 n번째`는 티켓 10에서 넣습니다.
덮어쓰기 허락 쌍·class 폴더 허락은 티켓 06이 요청 본문에 더합니다. 테이블(`job_overwrites`,
`job_targets.may_create_class`)은 이번에 미리 만들었습니다. 선택은 (대상, 레시피) 쌍(`job_pairs`)으로
저장하고 file 행은 쌍마다 만듭니다. 이번 요청은 대상 × 레시피 전부를 쌍으로 기록하며, 쌍을 빼는 것은
티켓 06입니다. 스냅샷 총량은 생성 때 디스크 사용량으로 한 번, 수집 중 남은 총량으로 다시 막습니다(넘으면
부분 스냅샷을 지우고 차단). 재기동 전에 한 번도 시작하지 않은 `대기` job은 재기동 뒤 수집될 수 있습니다.
이것은 처음 실행이지 다시 돌리는 것이 아니므로 "미완료 job을 다시 돌리지 않음"에 어긋나지 않습니다.
