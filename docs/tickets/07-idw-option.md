# 07: `.idw` 옵션

**What to build:** 실행자가 `.idw` 포함을 켤 수 있고(기본 끔), 켜면 "같은 idw를 쓰는 다른
레시피도 영향받음" 문구를 봅니다. 공유 `.idw`는 대상마다 한 번만 보냅니다.

**Blocked by:** 06

**Status:** ready-for-agent

- [x] job에 idw 포함 여부를 기록하고 스냅샷·manifest에 `data/{idw}.idw`가 들어감
- [x] 사전 점검과 첫 쓰기 전 재확인이 `.idw` 존재도 봄
- [x] 같은 대상에 같은 `.idw`는 한 번만 전송. job에 남은 레시피 중 그 `.idw`를 쓰는 것 하나라도 덮어쓰기를 허락받았으면 덮어쓰기 모드. 결과는 관련 레시피 모두에 보임
- [x] 화면: 켜고 끄기, 켰을 때 문구
- [x] pytest: 기본 끔이면 `.idw` 무전송, 켜면 대상당 한 번, 허락 계산

**Notes:**

- 공유 `.idw` 는 대상마다 file 행 하나이고, 작업자 대기열 맨 앞에 따로 한 항목으로 보냅니다.
- 첫 쓰기 전 재확인에서 덮어쓰기 허락이 없는데 `.idw` 가 대상에 생겼으면 그 `.idw` file 만
  `failed`("확인 뒤 대상에 생김")이고, 그것을 쓰는 레시피의 `.idp`·raw 파일은 그대로 진행합니다.
  스펙 문장("그 쌍은 전부 failed")을 그대로 따르면 `.idw` 하나 때문에 그것을 쓰는 레시피 전부가
  빠지는데, `.idw` 는 여러 레시피가 함께 쓰는 별도 파일이라 그 파일 하나의 실패로 두는 편이
  일관됩니다. 대상의 기존 `.idw` 는 바이트 그대로 남습니다.
- 사전 점검은 `include_idw` 일 때만 대상 항목에 `idw_exists`(이미 있는 `.idw` 의 idw 이름들)를
  붙입니다. 확인 팝업은 이것을 그 idw 를 쓰는 레시피의 "이미 있음"으로 보고 덮어쓰기를 묻습니다.
- 원본에 요청한 `.idw` 가 없으면 job 은 `차단("수집 오류: idw 파일이 없습니다: …")` 입니다.
- 확인 팝업의 총 크기에는 `.idw` 크기가 빠집니다(수집 전이라 모름). 파일 수에는 넣고 크기 옆에 "+ .idw" 를 붙입니다.
