# 07: `.idw` 옵션

**What to build:** 실행자가 `.idw` 포함을 켤 수 있고(기본 끔), 켜면 "같은 idw를 쓰는 다른
레시피도 영향받음" 문구를 봅니다. 공유 `.idw`는 대상마다 한 번만 보냅니다.

**Blocked by:** 06

**Status:** ready-for-agent

- [x] job에 idw 포함 여부를 기록하고 스냅샷·manifest에 `data/{idw}.idw`가 들어감
- [x] 사전 점검과 첫 쓰기 전 재확인이 `.idw` 존재도 봄
- [x] 같은 대상에 같은 `.idw`는 한 번만 전송. job에 남은 레시피 중 그 `.idw`를 쓰는 것 하나라도 덮어쓰기를 허락받았으면 덮어쓰기 모드. 결과는 관련 레시피 모두에 보임
- [x] 화면: 켜고 끄기, 켰을 때 문구
- [x] pytest: 기본 끔이면 `.idw` 무전송, 켜면 대상당 한 번, 허락 계산

**Notes:**

- 공유 `.idw` 는 대상마다 file 행 하나이고, 작업자 대기열 맨 뒤에 따로 한 항목으로 보냅니다. 맨 뒤라서
  쌍들의 첫 쓰기 전 재확인은 이 job 이 올린 `.idw` 가 아니라 원래 대상에 있던 것을 봅니다.
- 첫 쓰기 전 재확인은 스펙대로 `include_idw` 이면 `.idw` 도 봅니다. 덮어쓰기 허락이 없는 쌍은 대상에
  `.idw` 가 생겼으면 아무것도 쓰지 않고 전부 `failed`("확인 뒤 대상에 생김")입니다. 그 대상의 `.idw`
  행은 그것을 쓰는 쌍 중 허락받은 것이 있으면 덮어쓰기 모드로 보내고, 없으면 자기 재확인에서 같은
  사유로 실패해 대상의 기존 `.idw` 가 바이트 그대로 남습니다.
- 덮어쓰기 허락은 쌍마다 하나이고, 그 쌍의 `.idp`·raw 파일과 그 쌍이 쓰는 `.idw` 를 함께 덮습니다.
  사전 점검에서 `.idw` 만 있었어도 허락하면 그 쌍의 `.idp`·raw 도 덮어쓰기 모드가 되고 재확인을
  건너뜁니다. 그래서 확인 팝업은 대상에 `.idw` 가 있으면 레시피가 있든 없든 늘 `.idw` 이름을 밝힙니다.
- 사전 점검은 `include_idw` 일 때만 대상 항목에 `idw_exists`(이미 있는 `.idw` 의 idw 이름들)를
  붙입니다. 확인 팝업은 이것을 그 idw 를 쓰는 레시피의 "이미 있음"으로 보고 덮어쓰기를 묻습니다.
- 원본에 요청한 `.idw` 가 없으면 job 은 `차단("수집 오류: idw 파일이 없습니다: …")` 입니다.
- 확인 팝업의 총 크기에는 `.idw` 크기도 들어갑니다. 원본 요약 API가 `data/` 를 한 번 더 LIST 해서 `idw_bytes` 로 돌려주고, 팝업은 남은 쌍의 (대상, idw) 마다 한 번씩 더합니다. `include_idw` 인데 원본에 `.idw` 가 없으면(`idw_bytes` null) 요약 실패처럼 사유와 "다시 조회"를 보여 주고 실행을 막습니다.
