# 10: 스케줄러

**What to build:** 여러 job이 동시에 오면 FIFO로 줄을 서고, 장비가 겹치지 않으면 같이 돌며,
화면에 "대기 n번째"가 보입니다.

**Blocked by:** 05

**Status:** done

- [x] 큐는 `job_id` 순. 미완료 정의는 스펙대로(끝난 `uncertain`은 장비를 점유하지 않음)
- [x] 시작 조건 셋: 앞선 미완료 job과 장비(원본·대상) 겹침 없음, N ≤ 남은 예산, 앞에 예산 대기 job 없음
- [x] 시작 때 N 슬롯 예약, 원본 수집은 그중 하나를 씀, 마지막 작업자가 끝나면 해제
- [ ] 시작 판정에서 N > 상한이면 사유와 함께 종료(행 없으면 `차단("상한 초과")`, 있으면 `pending` → `failed`)
- [x] `GET /api/jobs`에 대기 순번, 화면 표시
- [x] pytest: 겹침 대기, 겹치지 않는 job 동시 시작, 예산 대기와 추월 금지, 상한 축소 종료, 대기 순번

**Notes:** 상한 초과 종료 중 `차단("상한 초과")`(행 없음) 경우만 구현했습니다. 행이 있는 경우는
이미 시작한 job이 재기동 뒤 다시 판정받을 때만 생기는데, 재기동 전에 시작한 job을 이어 돌리는
일이 티켓 12라 지금은 그 job이 스케줄러에 들어오지 않습니다. 같은 이유로 그런 job은 장비도
슬롯도 쥐지 않습니다. 남은 `pending` → `failed("상한 초과")`는 티켓 12에서 붙입니다.
