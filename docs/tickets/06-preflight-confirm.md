# 06: 사전 점검과 확인 팝업

**What to build:** 실행 전 확인 팝업이 대상마다 상태를 알리고 실행자가 고릅니다. class 폴더가
없으면 "만들까요?"(거절하면 그 대상만 빠짐), 다른 fab에 같은 class가 있으면 경고, 같은
레시피가 있으면 덮어쓸지 고릅니다. 허락받은 (대상, 레시피) 쌍만 덮어쓰기 모드로 보냅니다.

**Blocked by:** 05

**Status:** ready-for-agent

- [x] `POST /api/preflight`가 `class_missing`, `class_exists_other_fab`, `recipe_exists`를 읽기만으로 돌려줌
- [x] job 생성은 선택(대상, 레시피, 허락 쌍, 폴더 허락 대상)을 그대로 기록하고 사전 점검을 다시 돌리지 않음. 허락 쌍·폴더 허락은 job 자신의 선택 안이어야 함
- [x] 폴더 허락 대상은 class 폴더(`{class}/`, `{class}/data/`)를 만들고 진행. 거절한 대상과 허락 안 한 쌍은 job에서 빠짐. 남는 게 없으면 생성 거부
- [x] 허락받은 쌍은 덮어쓰기 모드, 나머지는 05의 첫 쓰기 전 재확인
- [x] 확인 팝업에 장비 수·레시피 수·파일 수·총 크기
- [x] pytest: 세 항목, 폴더 생성 후 복사, 거절 대상 제외, 허락 쌍만 교체, 허락 없는 쌍은 대상 무변경

**Notes:** 확인 팝업의 파일 수·총 크기는 수집 전이라 서버가 모릅니다. 고른 레시피마다 원본의 요약 API를 불러 (raw 파일 수 + `.idp` 1개)와 (raw 폴더 총 크기 + `.idp` 크기)를 남은 쌍마다 더합니다. `.idp` 크기는 요약 API가 idw 폴더를 한 번 더 LIST 해서 `idp_bytes`로 돌려줍니다. 남은 쌍의 요약이 모두 오기 전에는 실행할 수 없고, 실패한 레시피는 사유와 "다시 조회"를 보여 줍니다. 사전 점검을 시작할 때 선택을 복사해 고정하고 점검·팝업·job 생성에 같이 쓰며, 점검 중이거나 팝업이 열린 동안 선택이 바뀌면 결과를 버리고 다시 점검하게 합니다. 사전 점검에서 읽지 못한 대상은 팝업에서 사유와 함께 job에서 뺍니다. 폴더 허락이 없는 대상은 레시피마다 첫 쓰기 전에 `{class}/data/`가 있는지 보고(한 번 있었다는 사실을 허락으로 캐시하지 않음), mkdir도 `{class}/data/` 아래만 만듭니다. 작업 중 class 폴더가 없어지면 다시 만들지 않고 그 대상의 남은 파일을 "대상에 class 폴더 없음"으로 실패 처리합니다.
